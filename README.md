# 灵动月历 Android · 同 Wi-Fi 同步版

与配套 Windows 版双向同步，不需要云服务器或注册账号。

## 当前交付状态

本项目包含 Android 源码、构建工作流以及可运行的 Windows 版。**当前压缩包不含 APK：Android SDK 在制作环境中不可用，尚未完成 Android 编译、安装和实机配对验证。** 获取 APK 后再按以下步骤配对。不能把网页预览当作已安装的 Android 应用。

## 配对方法

1. 电脑先退出旧版日历，将配套的 Windows 程序完整解压到固定文件夹。保留原来的 `calendar.json`、`preferences.json` 与备份文件；不要从压缩包中直接运行。
2. 电脑和手机连接同一个 Wi-Fi。电脑小部件右上角「··· → 手机同步（同一 Wi-Fi）」中点击「开启同步」；完整管理窗口的「更多」菜单也有入口。
3. 在手机「同步」页输入电脑显示的 HTTPS 地址与配对码。存在多个地址时选择与手机处于同一网段的地址。配对码仅向自己的设备提供。
4. 配对后自动合并两端事项。手机应用在前台时约每 2.5 秒检查一次，回到应用也会检查。电脑端立即显示成功上传的修改。
5. 断网时继续编辑，重新连上后再合并。同一条事项在两端同时修改时，手机会显示冲突并让你选择保留手机或电脑版本。

电脑需保持程序运行且未睡眠。这里的同步不包含跨互联网同步，也不保证手机后台持续同步。Windows 若询问网络访问，按需仅允许专用网络；无需关闭防火墙或设置公网端口映射。访客 Wi-Fi、AP 隔离或企业网络策略可能阻止设备互联。电脑 IP 改变后，在手机重新填写新地址与原配对码即可。

## 功能

- 六周月历，显示跨月日期，日期下直接显示一条日程摘要及更多数量；点选日期查看、编辑当天全部事项。
- 农历、春节、元宵、端午、中秋、除夕与二十四节气等；农历由 Android WebView 的中文历法实现提供，节气为天文近似计算。不是官方调休安排表。
- 新增、编辑、删除日程或待办；分类配色、完成状态、备注、每天/每周/每月/每年重复、重复截止日。
- 手机本地资料加密保存、JSON 导入导出，与桌面备份格式兼容。导入按编号添加新事项，已存在编号不覆盖。
- 手机通知需要开启通知权限；采用普通系统闹钟，省电设置可能延后通知。不承诺精确闹钟或后台即时同步。

手机月视图可直接查看日程摘要；本版尚未提供 Android 主屏幕小部件。

## 资料位置

Windows 的日程仍为 **exe 同目录的 `calendar.json`**，上次版本是 `calendar.json.bak`；界面设置为 `preferences.json`。同步相关的 `lan-config.json`、`lan-state.json` 及 `lan-*.dat` 也在 exe 旁边。`lan-state.json` 保存版本与删除记录，部分文件通过 Windows 当前用户加密保护配对身份。不要单独回滚同步记录或同时运行两份同目录程序。

Android 按系统要求保存在应用私有目录 `no_backup/calendar-state.enc`，使用 AndroidKeyStore 与 AES-GCM 加密。手机不会写入安装目录或要求全盘文件权限。需要可见文件时，在「同步 → 导出 JSON」选择保存位置。卸载或清除应用资料会删除手机的本地资料，因此先导出备份。Windows 与手机的加密身份文件不能互相替代。

一份手机资料绑定一台电脑的同步身份。更换电脑前先导出手机与电脑备份；迁移整套 Windows 文件时保留同步记录。Windows 用户变化时需要重新配对。

## 构建 APK

要求 JDK 17、Gradle 8.9、Android SDK Platform 35、Build Tools 35.0.0。Android 8.0（API 26）及以上可安装。项目没有第三方运行时库，使用系统 WebView（建议保持更新）。

在项目根目录运行：

```text
node tests/sync.test.cjs
node tests/calendar.test.cjs
gradle -p android assembleDebug --no-daemon
```

APK 输出：`android/app/build/outputs/apk/debug/app-debug.apk`。

`.github/workflows/android.yml` 已配置 GitHub Actions。将本目录内容放到空仓库根目录后，提交 Android 源码会触发构建；也可在 Actions 页面手动运行。成功后下载 `LingCalendar-Android-debug` 构建产物。

首次构建采用调试签名。后续升级需复用同一签名；工作流支持仓库机密 `DEBUG_KEYSTORE_BASE64` 以保存自己的调试签名。未固定签名时，不同构建的 APK 可能无法覆盖安装；请先导出备份，避免为重装而丢失资料。正式长期使用前应配置自己的发布签名，不要把签名私钥提交进仓库。

## 验证范围

自动化验证覆盖离线合并、冲突、重试、删除墓碑、保存失败回滚、重复事项、农历节日与跨月日期。Windows 的存储与 UI 回归检查已通过。制作环境的连接策略阻止了加密回环请求；真实 Wi-Fi 传输与手机安装、界面、通知仍待 APK 构建后验证。详情见配套 `validation` 文件夹。
